# デザインのくわしい決めごと

見た目・写真・付箋の動き・図解・入力の流れ・結果の絵のくわしいことと経緯。CLAUDE.md の「デザインの決まり」の元の文。言葉で検索して、さわる所だけ読む。

## 1画面におさめる
- 方針の1のくわしいこと
   - **ツールの部分は、できるだけスマホの1画面におさめる**（入力から答えまで、スクロールしないで見える。目安は幅390px・高さ660px。`python3 scripts/check-fold.py` で点検。上下の欄やボタンがくっついていない＝あいだ6px以上かも見る。ツールを足したら `CASES` に足す。返礼品のページは `HENREIHIN=fixture npm run build` でビルドしたときだけ点検し、ないときはとばす）
   - そのために：ヘッダーは細く、パンくずはページの下、h1 とリードはつめる。名前は欄の中（希釈の「できあがり・原液・水」）、見出しと入力は1段（レシピの「レシピ／つくる」）、クリアは表の見出しの右（単価・レシピ）か、結果の紙の右上（ほかのページ）。答えは入れた所のすぐ近くに出す（レシピは行のすぐ下に赤で）

## デザインの決まり（しょーくんの方針・10/16、見た目は10/17に「方眼ノート」へ）
- **AIっぽい見た目にしない**（しょーくんの方針・10/17）。使わないもの：クリーム色×オレンジ（Claude の色に近い）、どこも同じ丸い角のカード＋うすい影、線のアイコンを色つきの四角に入れたもの、右はしの「›」や「→」、グラデーションの飾り、キャッチコピー。10/22 の共通ルール（プロジェクトの `claude/site-principles.md`）で足したもの：枠の左はしの太い色の帯、同じ大きさの四角いボタンを横に並べた切りかえ（えらんだものだけ色をぬる形も）、行の右はしの小さな「見る」「詳しく」、「準備中」「NEW」のような小さなバッジ（制度の変更点の「前から・この年・まだ」や返礼品の「定期便」は枠のない字にした）。**絵文字も使わない**（しょーくんの方針・10/17。✨🚀💡✅📌🎯🔥👉📝 のような AI がよく使う絵文字は、画面・文章・共有画像のどこにも入れない。`verify-dist.mjs` が点検する）
- **見た目は「家計簿の方眼ノート」**：白い紙に青い方眼、字と線は紺のペン（`--text`）、値をえらぶ所は**付箋**（下の「値をえらぶ付箋」）、えらんだ付箋に**赤ペンの丸**（`.tile`・`.seg-btn` の `::after`）、h1 は**黄色のマーカー**、計算カードは**マスキングテープでとめた紙**、答えの数字は赤ペン（`--red`）。角は小さく（3〜4px）、影はつけない。ボタンは文字だけ（アイコンなし。人数の −／＋ だけは記号）。ロゴは「計」の赤いはんこ（`LOGO_SVG`・`public/favicon.svg`・`make-images.py` の `logo` をそろえる。タブ用の `favicon.ico`（16・32・48px）とホーム画面用の PNG は `make-images.py` が作る。絵を変えたら `layout.mjs` の `ICON_V` と `manifest.webmanifest` の `?v=` を1つ上げて、スマホに残った古いアイコンを読み直させる。10/23 しょーくんのスマホに最初のオレンジのアイコンが残っていた）。トップのツール一覧はノートの目次（点線で区切った行）。「よく使う計算」だけは、ペンで線を引いた表に答えの小さな絵（`src/doodles.mjs`。文字なし・線のゆれは線の形に）と名前（10/27 しょーくんが3案から B）
- **写真の質感**（10/27 しょーくんが2案から「Canvaの写真」をえらんだ。「近代的なサイト感」）：生活のテーマのマスキングテープ・付箋（黄・水色・ピンクは同じ写真の色ちがい）・値札は、Canva の generate-image で作った写真（`public/img/`。元の書き出しは `scripts/art/canva/`。切り抜きは白を透明に）。字と数字はいままでどおり HTML で写真の上にのせる。影は写真のものだけ。結果の絵も写真（レシート・日めくり・結果の紙・値札、10/27 夜にボトル・ボウル・レシピのメモ・体重計の窓・ポイントのカード）。ボトルとボウルは白い背景のまま `mix-blend-mode: multiply` で重ねて、中の水や方眼を透かす。のびる紙は `border-image` で、はし（ちぎれ目・ぎざぎざ・角）はのばさない。共有画像（`make-images.py`）も同じ写真を使う（`photo`・`nine`・`multiply`）。写真は WebP で軽く（1枚20KBまで）、全ページで使い回す。お仕事の書類の紙はほぼ平らなので色だけ
- **部品と操作はどのページも共通**、紙・インク・表紙はカテゴリごと（端末のダークモードには連動しない。テーマは `src/site.mjs` の CATEGORIES → `<body data-theme>`）
  - 生活（主婦・学生）`seikatsu`・トップと固定ページ `home`：家計簿の方眼ノート（上のとおり）
  - 大人・ビジネス向けは**システム手帳と万年筆**（しょーくんの方針・10/17「大人でシック、でもサイト全体の統一感」）：ヘッダーとフッターは革の表紙にステッチ、計算カードはテープのかわりにリフィルの穴、見出しは明朝、h1 はマーカーのかわりに万年筆の下線、本文の見出しは二重線。付箋とえらんだものの丸は同じ（付箋の紙はテーマの色、丸の線を細く）
    - お仕事（会社員）`shigoto`：紺の革、白いリフィルに罫線、ブルーブラックのインク、えらんだものはボルドー
    - FX（トレーダー）`fx`：黒の革、暗いリフィル、白いインク、えらんだものは金
- **図解の式と帯の図**（10/28 しょーくん「図解の式最高じゃん」「文じゃなくて図や絵で、誰でも理解できるを徹底」。#70）：「計算式」は絵の式（`src/zukai.mjs` の `stair`：結果の絵の「もの」で、入れる数字 → 赤ペンの矢印と計算 → 答え（赤）を階段に。字は HTML、figcaption に式の文）、「計算例」の表の上に帯の図（`band`：もとの量の帯を答えの分かれ方に分け、下に目もり、答えに赤ペンの丸。斜線は SVG の線）。これから作るツールもこの形で、1つの絵は390pxで1画面（660px）まで。ふるさと納税と楽天のポイントは #80（式にならない判定・日付は、同じ階段で決まりの言葉をはさむ流れの図。図の数字は `tests/zukai-furusato-point.test.mjs`）。生活の割引・まとめ買い・傾斜割り勘・レシピ・洗剤・塩分濃度・使いみち別の3つは #81（使いみち別は「計算のしかた」の節。図の数字は `tests/zukai-seikatsu.test.mjs`）。電気代・家電別の5つ・灯油代・BMI・偏差値・第何曜日・和暦・学歴は #82（家電別は強さごとの棒・電気代の式は `src/denki.mjs` の `denkiZukai`。図の数字は `tests/zukai-kurashi.test.mjs`）。家族の行事の5つ・お仕事の9つ・FX の4つは #83（行事は数え方がちがうことを図の下の文にも書く。FX の暗い紙は `site.css` の `[data-theme="fx"] .fz-box` など。図の数字は `tests/zukai-shigoto.test.mjs`）。これで全ページ
- 計算カードはシンプルに、**押しやすく大きく**：よく使う値は大きな付箋（割引は「30%」と「3割引き」を両方書く・半額・最後の付箋は自分で入力）。おまけのオン・オフ（さらに割引・2つくらべる・浪人1年 など）は、結果の下の**チェック欄**（□に赤ペンの✓。`.calc-tools` の `aria-pressed` のあるボタン。もう一度押すと元にもどる。押すだけのボタンには `aria-pressed` を付けない）。欄がふえて窮屈になる機能は、下のページに分けて、ボタンはそのページへのリンクにする（`.tool-link`。割引計算の「何％オフ？」、実質単価の比較の「入り数・割引シール」。10/21 しょーくん）。小さな切り替えスイッチや文字だけのリンクは使わない。端数の選択などは必要なときだけ出す。入力の形そのものを選ぶとき（希釈率の「薄め方：？倍・？：？・？％」）は、入力の上に `.seg`（付箋を横に並べたもの。高さは `--ctl-h`）
- **値をえらぶ付箋**（10/22 しょーくん「付箋のほうが断然好き」「昔の数字を打つだけのサイトとは全然ちがうアニメーションを」）：`.tiles`・`.seg` の中の `.tile`・`.seg-btn` は、整頓して並べた付箋（傾きは ±0.5° まで）。紙の色はテーマごと（`--note`）、えらぶ場所ごとに色を変える（`layout.mjs` の `numberNotes` が上から `data-note` 1〜3 を付ける。生活は黄色・水色・ピンク）。はじめから入っている値（消費税10%・ひとり など）は計算に使うが、えらんだしるしは付けない（`data-fresh`。10/22「デフォルトで丸つけてないほうがいい」）。入れた数字に合わせて計算のスクリプトが付箋をえらんだとき（和暦の元号・掛け率）は答えの一部なので丸を付ける。さわってえらぶと、ほかの付箋は下のはしからめくれて剥がれて飛んでいき、えらんだ付箋は先頭へすべって、赤ペンで丸を描き、右下がめくれて少し斜めに。えらんだ付箋をもう一度さわるか「クリア」で貼り直す。動きは `src/client/notes.js`（`.tiles`・`.seg` のあるページに `layout.mjs` が入れる。計算のスクリプトにはさわらない。動きを減らす設定の端末では動かさない）。自分で入れる付箋（?%）はさわっても剥がさない。`check-fold.py` は付箋の動きが終わってから測る
- **ボタン・選択肢はなるべく増やさない**（しょーくんの方針・10/16「ボタンや選択肢が多いと直感で使いにくい」）。どれか1つわかれば計算できる量（希釈の「できあがり・原液・水」）は、モードのボタンを作らずに欄を並べ、入れた欄から残りの欄に答えを出す（答えの欄は点線の枠に赤ペンの数字。さわると、まるごと書きかえられる）。単位の選択も、なくせるならなくす（ml だけにして、1,000ml からは「＝1L」を添える）。手順の番号や「わかっている量を1つ入れる」のような見出しは置かず、まだ入れていないときの案内を答えの下に1行で出す
- **入力の流れは上から下へ**（10/21 しょーくん「どのフォームに何を入れたらいいか、直感でわかるように」「この原則をこのサイトのテンプレートに」）。どのツールもこの形で、新しいツールもこれで作る
  - 答えの下の案内は、まだ入れていない欄のうち、いちばん上の欄の名前を出す（「元の値段を入れてください」→「値引きをえらんでください」、単価の「Aの量を入れてください」）。どれから入れてもよい欄（利益率の3つ）は「原価か利益率を入れてください」のように残りを出す。1行に入らない長さにしない
  - 名前だけでは何を入れるか迷う欄（残業代の深夜・休日・月給・年間休日・1日の所定時間、FXの口座のお金・ロスカットの基準）は、さわっている間だけ、入力の段の下に1行の説明（`boxField` の `hint` → `data-hint`、`ui.mjs` の `focusHints`。中身はよくある質問の答えと同じ。全角21文字まで、`verify-dist.mjs` が点検）。見ればわかる欄には付けない
  - Enter は次に入れる欄へ。答えの欄（点線の枠）はとばし、最後はキーボードを閉じる。次がタイルをえらぶ所なら閉じる（割引計算の元の値段）
  - 空にした欄は、入れた欄から外す（利益率・清掃。前に入れた数字を答えで上書きしない）。答えでなくなった欄は空にする
  - 名前を欄の中に書いた入力欄（`box-field`）も、ほかの欄と同じ高さ（`--ctl-h`）
  - 入力の段は左右のはしをそろえる（10/22 しょーくん「クリアと店舗の名前があるせいで、四角が左右にでこぼこして見える」「でこぼこしてるのは見ずらいから、全て直して」）。−／＋は、名前を中に書いたまん中の欄（`.box-stepper`。レシピと割り勘の人数・お買い物マラソンの店舗・ワンストップ特例の寄付先）にして、欄の外に名前を置かない。クリアは欄の横に置かず、結果の紙の右上（書類 `.doc-clear`・レシート `.rc-clear`・お知らせやカレンダーの紙は題の右・履歴書は「学歴」の右・値札の台 `.stage-clear`・FX はチャートの上の帯の右）か表の見出しの右。えらぶ段の名前（割り勘の単位・消費税の1円未満）は横ではなく上に。マスは数で列をそろえる（2つなら2列）。`scripts/check-edges.py` が全ページで点検する（わざと形がちがう希釈のボトルなどは ALLOW）
- くらべるツールは表の形：見出し1行（`.cols`「値段（円）・量」）＋商品ごとの行（`.item` の A〜H の丸＋`.pair`）。最初は4行、「＋1つ追加」で8行まで（まとめ買いの単価比較は、商品ごとに入り数・割引シールの段があるので、最初は2つ・4つまで。商品のあいだは点線）。単位は入力欄の右の `.unit-select`（iPhone では大きな選択画面）。結果は「いちばんおトク」の大きな値札＋安い順の順位と棒グラフ（`.rank`。棒の長さはそろえた幅でくらべる）
- **結果は、答えの数字を書いた1枚の大きな絵**（10/21 しょーくん「結果は図で、一番大きく」「他サイトと比較して、ビジュアルを売りに」）。生活はお店や台所や家のもの（割引＝値札、実質単価＝値札と順位の棒グラフ、レシピ＝人数分のお皿とマスキングテープでとめたメモ、希釈＝ボトルに原液と水の量、割り勘＝お会計のレシートと人数分の券、電気代＝電気代のお知らせとメーターの数字）。お仕事は書類（`.doc`：明朝の題、見積書の金額の欄のように二重線を引いたいちばん大きな数字、明細の表。残業代＝残業代明細書、利益率＝利益計算書と粗利率のはんこ、清掃＝作業指示書と床の図）。FX はトレードアプリの画面（`.chart`：ロスカット＝いまのレートとロスカットのラインのチャート、スワップ＝1年でたまる額の階段のチャート、証拠金維持率＝口座の画面の大きな半円のメーター。線の形は `src/lib/fx-chart.mjs`）。答えの数字は絵の中に書いて、絵を大きくしても答えは1画面に入れる（入らないときは、答えを絵の上の段に）。ビジュアルは HTML/CSS/インラインSVG で作り、外部の画像を読まない。共有画像（`make-images.py`）も同じ絵にする。紙の結果（レシート・書類・電気代や灯油代のお知らせ・レシピのメモ）は、入力欄の白と見分けられるように紙の色 `--sheet`（うすいベージュ #f3f1ea。10/21 しょーくん「紙モチーフの結果は少し紙っぽい色にして、入力フォームと識別」）。共有画像（`SHEET`）と割り勘の「画像で送る」も同じ色。紙の上に貼ったもの（灯油のラベル・メーターの数字）は白のまま

# 読みもののネタの山と書き方

予約タスク「読みもの書き（4サイト）」が、木曜と日曜にここから1本書いて公開する（しくみはプロジェクトの `claude/sodatsu-spec.md`。2026-11-04 しょーくんと決定）。このファイルと CLAUDE.md だけで1本書けるようにしてある。ネタの山は 11/4 にしょーくんが OK した（計算のページと同じ答えになるネタは、同じ日に切り口を変えた）。

## 書き方

### 置く場所と作り方
- 読みものの棚（docs/sodateru.md の「読みものの棚をつくる」）ができてから書く。main に `src/pages/yomimono.mjs` がなければ、書かずに飛ばす（報告ファイルに「- 読みもの：止めた（読みものの棚がまだない）」）
- 1本＝1ファイル `src/yomimono/<slug>.mjs`。ひな形 `src/yomimono/_hinagata.mjs` をコピーして書く（`_` で始まるファイルはビルドが読まない）。slug はローマ字の短い名前（例 `danbou-hikaku`）で、URL は `/yomimono/<slug>/`。一度公開したら変えない
- ファイルの中身は `export default { … }` と `export const NUMS = { … }`（棚の形。ひな形のとおり。tests/yomimono.test.mjs の `checkYomimono` が欄を点検する）
  - `slug`（ファイル名と同じ）・`title`（h1 と、title「題｜読みもの｜サクッと計算」の頭。問いか短い言い切りの文）・`lead`（1行。全角21字まで。半角は0.55で数える）
  - `category`：src/site.mjs の CATEGORIES の id（seikatsu・gyoji・shigoto・furusato・point・fx）。手帳の見た目と、見張る言葉が決まる
  - `tools`：つなぐ計算の slug（src/tools.mjs の published）。1つめが「自分の数字で確かめる」の行き先で、共有画像もその計算のものになる
  - `published`・`updated`：日付（日本時間の YYYY-MM-DD）。棚は published の新しい順。ページの h1 の下に、同じ日なら「◯年◯月◯日公開」、ちがえば「◯年◯月◯日更新」が出る
  - `description`：全角80〜120字・数字入り・ほかのページと同じにしない
  - `body`：h1 とリードのあとに入る HTML。節は `section(id, 見出し, 中身)`（src/layout.mjs）で作り、図は `src/zukai.mjs` の部品で描く。節の id は `ym-` で始めない（棚が出す節の id。字数の数えから外れる）。h2 が3つ以上あると、パソコンでは左に目次が出る
  - `faqs`：0〜3問（検索で使われていそうな問いだけ。`{ q: '問い', a: '<p>答え</p>' }`。答えは1〜2文）。0問なら節も FAQPage も出ない
  - `sources`：`{ name, url, checked, what }` の並び（url は https）。出典の節に「名前のリンク（何を、◯年◯月◯日に確認）」の形で出る
- 本文に出す数字は src/lib の計算か src/data のデータから作る（手で打たない）。本文に出す数字は `export const NUMS = { … }` にまとめ、`tests/yomimono-<slug>.test.mjs` で、自分で確かめた値と比べる
- src/data の数字を使うときは、そのデータに書いてある出典と確認日を、そのまま出典の節に使ってよい（開き直さなくてよい）。新しい数字だけ、ネタの行の URL か WebSearch で開いたページで確かめる
- 一覧（/yomimono/）・トップの「読みもの」・計算のページの「この計算の読みもの」・RSS・サイトマップには、ファイルを足せばビルドで自動で入る。src/tools.mjs はさわらない（つなぐ計算の `updated` も変えない）
- コマンド：`npm run check`（テスト → ビルド → 全ページ点検）。見た目は `python3 -m http.server 8766 --directory dist`（Bash の run_in_background で起動）で開き、Playwright でスマホ（390px）とパソコン（1280px）を撮って確かめる
- ブランチは `claude/yomi-<slug>`、PR の題は「読みもの：<題>」

### 書く前に：計算のページと重ねない
- tools に入れる計算のページ（src/pages/ の中。tools.mjs の slug から探す）の本文とよくある質問を grep する。同じ問いに同じ答えをしている所は、1文でふれて計算のページへリンクするだけにし、ページにないこと（ほかの計算との組み合わせ・場面ごとの例・運営者の話・くらべた表）を書く
- ページにないことだけで 1,200字に届かないネタは書かずに飛ばし、行の終わりに「（飛ばした：計算のページと重なる）」と足して山のいちばん下へ動かす

### 中身
- だれのどんな問いに答えるかは、ネタの行のとおり。答え（数字入り）を最初の1〜2文で書き、そのすぐ下に図を置く
- 長さ：読みものだけの決まりで、自分の文 1,200字以上（計算のページは 900字）。数えるのは body の .prose の節の文字で、表・見出し・SVG の中はのぞく（図の箱の字と figcaption は数に入るが、それで字数をかせがない）。棚が出す「自分の数字で確かめる」「出典」「ほかの読みもの」の節は数えない。目安は 1,500〜2,500字。水増しはしない（同じことを言いかえない・前置きやまとめの段落を書かない）。足りないと `npm run check` が止めるので、書き足してから出す
- 節（h2）の例：なぜそうなるか（式と、その式になる理由）／場面ごとの計算の例（2〜3。数字と答えつき）／まちがえやすいところ／くらべた表・早見表（データか src/lib の計算から作る）／運営者の現場の話（ネタの行にあるときだけ）。「使い方」の節は作らない
- 出典と確認日：数字・決まりは、メーカー・役所・公式のページで確かめたものだけ書く。会社の解説記事は言葉の意味を見るのに使ってよいが、数字はそこから取らない。確かめられない数字は書かない。公式の文を写さず、自分の言葉で短く
- 運営者の話：ネタの行と、下の「運営者から聞いた話」にある話だけを使う。足さない・ふくらませない（作り話は書かない）。「運営者の勤め先では」のように、だれの話かわかる形で書く。運営者の仕事は「ビルや病院の清掃と、職場の安全衛生の仕事」（このサイトについての文と同じ）。FX は「FXの取引も自分でしています」（このサイトについての文と同じ）より先は書かない（取引の経験をもとにした話は書かない）
- 最後につなぐもの：棚の「自分の数字で確かめる」の節が、tools の1つめの計算へつなぐ。本文の中でも、その計算の名前を出してリンクする。印刷の早見表がある計算（割引・希釈・年齢・学歴）は、その PDF にも1行でつなぐ。清掃・消毒の読みものは、合えば安全衛生の便利帳へ1文（例：「清掃作業監督者や病院清掃受託責任者の再講習の時期は、安全衛生の便利帳で調べられます。」→ https://anzen-benricho.com/shikaku/koushin/ ）
- 文章：CLAUDE.md の「文章の決まり」のとおり（です・ます／使わない言葉／太字なし／かっこは1文に1つ／キャッチコピーなし／3つ並べなし）。題は「〜を徹底解説」「完全ガイド」「〜とは？わかりやすく」のような形にしない
- 「ポイント」：楽天やAmazonのポイント（ためるポイント・制度の名前）は使ってよい。「大事なところ」の意味の「ポイント」と「コツ」は使わない
- 楽天のポイントの読みもの（category が point）は、/point/ と同じ言葉の決まり（お得・最安・必ず得・倍確定・予想・次回は など。verify-dist が見張る）と docs/point.md の決まり（公式で確かめたものだけ・楽天とは関係のない個人のサイトと書く）。ふるさと納税（furusato）は /furusato/ と同じ言葉の決まりと docs/furusato.md の決まり
- 神社・お寺・地域・会社でちがうものは、ちがうと書いて言い切らない。体や法律のことは、出典に書いてある範囲だけを書き、判断は言い切らない（「医師に」「勤め先や労働基準監督署に」確かめる、と書く）
- 同じ文を、ほかの読みものや計算のページにくり返し出さない（verify-dist の同じ形のページの点検と同じ考え）

### 絵
- 図解だけ（`src/zukai.mjs` の stair・band・zBox・zCal など）。図の中の数字と字は HTML の文字、SVG は role="img" と aria-label、figcaption に1行の文
- Canva は使わない（11/4 しょーくん。夜や予約タスクが待ち時間で止まらないように）。写真・外の画像・絵文字も使わない

### 公開
- 書いていない軽いモデルが点検する（文章の決まり・数字が出典やテストと合うか・作り話がないか・使わない言葉・計算のページと重ねていないか）。直してから PR
- PR の CI（build-deploy と、動いていれば check）がすべて緑になったら squash マージ。main への push で deploy.yml が動いて本番に出る（workflow_dispatch は要らない）。deploy が成功したかを確かめる
- 同じ PR の中で、ネタの行を「- [x] 題（PR #◯・日付）」にする。飛ばしたネタの行を動かしたときも、同じ PR に入れる
- 報告ファイル（プロジェクトの claude/reports/sakutto.md）に「- 読みもの『題』：公開（PR #◯）」

### 開けるページ
- ネタの行の URL と、WebSearch の結果の URL だけを開く（自分で作った URL は開かない）
- 行の URL がそのまま開けない（許可の一覧にないと言われた）ときは、WebSearch でそのページを出して、結果のリンクから開く（11/3 の夜 #116・#118 はこの形で開けた）
- 行に「WebSearch で◯◯」とあるネタは、その公式のページが WebSearch で出なければ書かない
- 開けない・出ないネタは飛ばして、行の終わりに「（飛ばした：開けない）」と足して山のいちばん下へ動かし、次のネタを書く

### ネタの選び方（山の [ ] が5本を切ったら、同じ PR で10本足す）
- 選んでよいもの：このサイトの計算（src/tools.mjs の published）につながり、計算のページにはない切り口のもの（ほかの計算との組み合わせ・場面の例・くらべた表・季節の問い）。図や表や計算の例で答えるとわかりやすい問い。季節の問い（冬の暖房・夏のめんつゆ・年度がわりの有給や入学・年末年始）
- 選ばないもの
  - 計算のページの本文やよくある質問と、同じ問いで同じ答えになるもの
  - 1行の答えで済むもの（検索画面のAIの答えで終わる）
  - しくみ・メリット デメリット・やり方の一般論（ふるさと納税は 10/23 の討論で「書かない」と決めた）
  - おすすめ・ランキング・還元率・コスパ・会社や商品やサービスの順位とくらべ
  - 楽天の次の回・予想・スケジュール・くじ・裏ワザ。ふるさと納税の返礼品のすすめ・節税のうたい文句
  - 金額・年収・都道府県・自治体ごとに、同じ形で量産するもの
  - 運営者の経験が要るのに、下の「運営者から聞いた話」にないもの
  - 体や法律の判断を言い切るもの
- 重ねないもの：もうある読みもの（src/yomimono/）と山の題。答えが同じになる題は1つにまとめる
- 足すときは、下の行の形で書く。資料の URL は、WebSearch で出して開けた公式のページだけ（作った URL は書かない）
- 足したネタは、サクッと計算のチャットでしょーくんが見る（合わなければ直す）

### 運営者から聞いた話（2026-10-31 しょーくんから。このまま使う・足さない）
1. トイレは男女で実際にかかる時間がちがう。雨の日は決まった回数より多く掃除しなければならない。衛生消耗品の補充は、よく使われるフロアほど回数や呼び出しが多い（どちらが長いかは聞いていないので書かない）
2. 勤め先では、薄めるときにゴーグルをつけるのが決まり。まぎらわしいボトルに入れない。薄めてから24時間以内に使い切る（運営者は「濃度が規定値を下回ると聞いた」。理由として書くのは、広島市のページの「薄めた液は時間がたつと効果がなくなるので作り置きしない」の範囲）
3. 人数や時間割は、スタッフどうしの相性や、一人ひとりの仕事の速さに応じて調整することが多い（性別・年齢は誤解されやすいので書かない。しょーくん 10/31）
